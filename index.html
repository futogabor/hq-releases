What it checks

Routine checks across repos, accounts, and agents

When you maintain multiple repositories, cloud logins, and AI coding tools on one Mac, small configuration mismatches are easy to miss. HQ checks the links between them in the background.

Wrong CLI accounts before a deploy

HQ reads project deploy configs — wrangler.toml, firebase.json, supabase, fly.toml, netlify.toml, vercel.json, and git remotes — and compares them against the accounts your CLIs are currently signed into before a push or deploy runs.

Secret filenames and commit emails

HQ checks your git index and commit history for secret filenames without opening their contents, and checks your configured and unpushed commit emails against the address you use for each repository owner.

Shared state for AI coding tools

Connect Claude Code, Codex, Cursor, Antigravity, and git in one step. Agents can read project briefs and run preflight checks through a local MCP server instead of rescanning disk, while account and renewal changes wait for your approval in HQ.

Inside the app

Six sections, derived from your files

HQ derives what it can from your project folders, lockfiles, git history, and installed CLIs. You only enter what cannot be derived: purpose, status, account ownership, plans, costs, and renewals.

Today & Inbox

Prioritized alerts

Separates vulnerabilities in shipped runtime dependencies from dev-only tooling, flags repositories that exist only on this Mac, and puts the highest-priority items at the top with Copy Fix and Copy Task buttons.

Projects & Preflight

Per-project status and guard

Shows branch state, unpushed commits, open GitHub PRs (including agent branches), live URLs, and a per-project push/deploy guard (Stop, Warn, or Off). Open any project in your editor or Terminal directly.

Accounts & Renewals

CLI logins, domains, and certs

Reads active logins for 18+ platform CLIs (gh, wrangler, supabase, firebase, vercel, aws, flyctl, netlify, gcloud, az, and more), alongside subscription renewals, RDAP domain expiry, and TLS certificate dates.

Vulnerability checks

Lockfile advisories and EOL dates

Opt-in built-in OSV scanning checks 14 lockfile formats (npm, pnpm, yarn, Python, Rust, Go, Swift, Ruby, PHP, Dart) against api.osv.dev — or uses osv-scanner automatically when installed — alongside endoflife.date runtime checks.

Disk

Disk space map and cleanup

Maps folder sizes across your home folder and attached drives as a zoomable Voronoi map, lists rebuildable node_modules, DerivedData, .next, and target directories, and moves git-ignored build folders to Trash only when confirmed.

Native Mac app

Fast search and external drives

Built in Swift and SwiftUI. Use Cmd-K to jump to projects, accounts, live sites, or actions, refresh a single project on demand, and keep projects on external drives listed even while the drive is unplugged.

Menu bar & lock

Menu bar mode and window lock

If you prefer not to keep HQ in the Dock, switch to menu bar mode in Settings. Scheduled background refreshes continue running, notifications fire for new serious items, and the popover opens recent projects or priorities directly.

  • Menu bar at login: Can open in the menu bar only at login, showing an attention dot when serious alerts or pending agent changes need review.
  • Quick project actions: Open recent projects in Antigravity, Cursor, VS Code, Xcode, or Terminal, or run a single-project refresh from the popover.
  • Touch ID and Apple Watch lock: Lock HQ's windows on sleep, idle, or via Ctrl-Cmd-L while agents continue using hq-mcp.

What agents can do directly

  • Query project briefs, preflight verdicts, alerts, renewals, and CLI login mismatches without rescanning disk.
  • Use the Core (8 tools) profile to keep startup context small, or switch to All (28 tools) anytime.
  • Add dated project notes, update project status, and record optional cross-agent session handoff reports.
  • Every registry edit is a git commit with a Via: trailer that you can undo with Cmd-Z.
Waits for approval

What requires confirmation in HQ.app

  • Changes to linked accounts, live site URLs, domains, and subscription renewals wait in Agents > Changes until you approve or reject them.
  • The hq CLI follows the same rules as MCP — an agent with shell access cannot self-approve changes or change guard modes.
  • Strings originating from repositories are marked as untrusted data to reduce prompt-injection risk.
  • Edits made directly in your registry folder outside HQ are detected and shown as a diff before being trusted.
Privacy & security

What HQ reads, and what it never does

HQ runs locally on your Mac with explicit limits on what files it reads, how it runs git, and which hosts it contacts.

No secrets

.env, key, token, and credential files are recorded by name and never opened. Passwords stay in Apple Passwords; HQ stores only the entry's name and redacts token-shaped strings before writing to disk or returning MCP results.

Read-only on scanned repositories

HQ never moves, renames, or deletes files in your projects (except moving a git-ignored build folder to the Trash after you confirm). Git runs with hooks, fsmonitor, custom filters, and lazy fetches disabled, and evicted iCloud files are skipped.

No telemetry and visible network log

No HQ account, no analytics, and no listening sockets. Every outbound request — GitHub via your own gh login, opt-in api.osv.dev, endoflife.date, RDAP/TLS checks, installed CLIs, and Sparkle updates — is listed in Settings > Network.

Plain local YAML and SQLite

Your projects and accounts are stored as plain YAML files in your own local git repository (~/HQ by default). Generated scan state and the append-only audit log stay in a private 0700 SQLite database in your user Library.

Questions

Frequently asked questions

Why is the GitHub repository called hq-releases?

futogabor/hq-releases is the public distribution repository for HQ. It holds the signed and notarized app zips under GitHub Releases, the EdDSA-signed Sparkle update feed (appcast.xml), issue tracking, and this page.

Does HQ contain AI or spend AI tokens in the background?

No. HQ has no AI model inside and spends no AI tokens on scans, login checks, vulnerability lookups, or push guards. It runs those checks locally on your Mac and exposes structured answers to the AI coding agents you already use.

Does HQ work with projects created in cloud tools like Lovable, Bolt, or v0?

Yes. Once a cloud-built project is cloned locally or added to your registry with its GitHub repository, HQ tracks its open pull requests, agent branches, CI checks, domains, and deployments alongside your local repositories.

Will HQ modify my agent configs or project files without asking?

No. HQ is read-only on scanned project folders (except moving a git-ignored build folder to Trash when you confirm). Agent MCP servers and guard hooks are only changed when you click Set Up in the app, and HQ creates a .hq-backup copy of edited hooks files.

How do I uninstall HQ or disconnect my AI agents?

Open Agents > Connect inside HQ and click Remove HQ from Agents to remove HQ's MCP entries and guard hooks. Then quit HQ and drag HQ.app from Applications to the Trash. Your YAML registry in ~/HQ remains untouched.
